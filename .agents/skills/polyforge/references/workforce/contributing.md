# Add one specialty

Start with one exact user requirement, domain and supported/experimental/reference
state. Prefer adding a source-attributed KnowledgeCard and focused reference when
there is no executable action. Include why/when, contrasting examples, prerequisites,
versions, risks, license, digest, fixed smoke probe and a confidence/reviewer record.

For executable support add a versioned typed capability to the canonical catalog,
bounded workspace/role permissions, expected editable artifacts and resource
budgets. Write a positive fixture and at least one negative test before production
code. Probe installed APIs, run real outputs, independent review and rollback
where writes are involved. Update command docs from the registry. Add a public
benchmark slot and keep separately controlled holdouts outside this workspace.

Only owner approval and measured workflow evidence can promote the reusable
action. Documentation, a model claim or a smoke-probe PASS cannot do so. Preserve
original brief/amendments and all unimplemented requirements. No automatic package
installation, historical prompt override or silent scope/quality reduction.
