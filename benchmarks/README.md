# Independent evaluation boundary

Public development fixtures are editable and visible to generators. They are
never held-out qualification. Independent evaluators freeze the original brief,
task identity, scoring version, rubric hashes, and budgets outside this repo.
No hidden briefs, answers, traces, or private scoring fixtures belong here.

Phase 11 implements public suite orchestration, immutable attempt ledgers,
tool-parity checks, separate task metrics and offline reports. The unavailable
grader returns BLOCKED and game PARTIAL. Authenticated external result
verification, protected access/leak probes and actual four-arm model trials
remain unmet inherited Phase 11 gates; they are not waived or moved to a later
phase by the availability report. See [the benchmark guide](../docs/benchmark.md).

Only COMPLETE_GAME_2D/3D attempts enter accepted-game rate. Asset, animation,
mechanic, and repair tasks have separate denominators. C/D must have identical
general Blender/Unity MCP tools, versions, permissions, and budgets. Preserve
failures/timeouts and separate cold installation from warm execution costs.

The original twelve public development tasks remain frozen. The
`release-development-v1` extension preserves those exact tasks and brief bytes
and adds two public complete 3D game specifications. The extension is visible to
generators and cannot count as an evaluator-owned holdout. One new specification
requires unsupported mechanics deliberately: preserve those requirements and
report gaps instead of substituting the available arena. A separately controlled
withheld variant and executable external scoring are still missing.

The default schedule honors the declared five runs per arm/task. Small declared
samples are exploratory; an explicit seed tuple must match the declared count.
External evaluator access or a budget being unavailable must remain visible;
do not invent results.
