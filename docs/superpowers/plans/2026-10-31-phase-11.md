# Phase 11 implementation plan

> For agentic workers: use subagent-driven-development for independent slices,
> with a fresh task review and final whole-change review. Execute sequentially
> where shared native/project state requires it.

**Goal:** implement and qualify every Phase 11 requirement while retaining honest
blocked release outcomes for independently owned evidence that is unavailable.

**Architecture:** extend existing Python/UPM capabilities, native evidence and
bounded workers; public benchmark runners and external evaluators remain separate.

**Tech stack:** Python 3.11+, existing jsonschema/pytest/ruff/mypy tooling,
Blender 5.2.2 and Unity 6000.6.3f1/URP 17.6.0 on Windows.

**Spec:** `docs/superpowers/specs/2026-10-31-phase-11-design.md` and the original
v5.1 blueprint. The authority and its complete gates take precedence.

## Global constraints

- Preserve original brief, unchanged Phase 0–10 artifacts and command compatibility.
- No untrusted execution, undeclared network, original-project Unity opening or
  raw serialized Unity asset mutation.
- Required FAIL/BLOCKED/REVIEW/NOT_RUN never becomes accepted fulfillment.
- Freeze source bytes during full qualification. Coverage bars remain >=90%.
- Commit/push after phase verification; preserve failed attempts and external gaps.

## Review focus

- Unstable/link-containing project trees must not escape or mutate inspection.
- Missing/forged benchmark outcomes must not become accepted games or valid parity.
- Fixture/model/seed/tool/budget changes must invalidate comparison identity.
- Performance samples must come from rendered standalone execution, with startup,
  warmup, sample counts, hardware, quality and stop conditions recorded.
- Same-host role labels cannot masquerade as native delegation or hidden judges.

## Task 1: unchanged baseline and complete gate inventory

- [ ] Full offline baseline, coverage and exact engine identity retained.
- [ ] Enumerate 11.1–11.12, deliverables, G1–G17 and cross-cutting obligations.
- [ ] Inspect current native fixtures and interfaces; record design decisions.

## Task 2: static original-project inspection

Files: new `polyforge/inspection.py`, tests `tests/test_phase11_inspection.py`;
parent integrates existing `inspect-project` registry/dispatch.
Interface: `inspect_project(project: Path) -> Result`, no writes/process launch.

- [ ] Write failing tests for inventory/GUID/version diagnostics and original hashes.
- [ ] Reject links, incomplete/unstable inventories and bounded-read exhaustion.
- [ ] Implement using existing path/result/JSON helpers; run positive and negative
  filesystem tests, lint/types and independent review.

## Task 3: truthful benchmark execution and reporting

Files: `polyforge/benchmark/{tasks,runner,metrics,analysis}.py`, bundled schemas,
tests `tests/test_phase11_benchmark.py`, baseline prompt/tool metadata and report.
Interfaces reuse `EvaluationRequest`, `BaselineRunner`, `AcceptanceEvaluator`.

- [ ] Freeze public suite/brief hashes and task-specific acceptance metadata.
- [ ] Tests first: missing runner/evaluator, actual failure/timeout, frozen inputs,
  parity mismatch, separate task denominators, unknown cost and finite metrics.
- [ ] Implement bounded orchestration with injected registered runners/evaluators;
  no dynamic source loading or engine-as-all-baselines shortcut.
- [ ] Wire historical CLI flags without breaking output/exit semantics; test
  dry-run zero writes and offline JSON/human/escaped HTML reports.
- [ ] Record four-arm trials and worker ablations actually available; unavailable
  host/evaluator paths retain explicit NOT_RUN/BLOCKED, no superiority claim.

## Task 4: native performance and second distinct game style

- [ ] Finalize native design from current game/sprite/asset infrastructure.
- [ ] Tests first for rendered standalone sample validity and mandatory second-style
  behavior; implement native APIs, independent oracle and bad-case mutants.
- [ ] Run actual pinned native gates and standalone profile: 1280x720, 10-second
  warmup, three 60-second samples; preserve all measured values and misses.
- [ ] Re-run original arena, animation/sprite and repair/race/crash regressions.

## Task 5: release and qualification

- [ ] Execute unfamiliar Blender/Unity API/version-change fallback cases.
- [ ] Check all historical/documented CLI syntaxes and runnable examples.
- [ ] Complete architecture/support/security/contribution docs and capability map.
- [ ] Freeze Phase 0–11 fixture digest; verify reproducible package builds and
  clean offline installation against final source bytes.
- [ ] Full suite/coverage, both-platform types, lint/format, docs, meaningful native
  and security checks; fresh broad review; fix confirmed findings and rerun affected gates.
- [ ] Report every row with authoritative evidence, including unmet external gates.
- [ ] Commit/push, inspect exact remote refs and all CI jobs. Tag/release only at
  the classification supported by actual qualification. Evaluate Phase 12 entry
  without weakening unresolved Phase 11 requirements.
