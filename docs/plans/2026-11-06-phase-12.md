## Scope and selected design

Extend the engine with a bounded, typed modeling plan compiled from four
parameterized families and an explicit composition request. Reuse existing
RunContext, WorkspacePolicy, owned ProcessPolicy, FileLock, RunJournal,
artifact registries, workforce seals/reviews and CLI dispatch. Existing recipe
schemas and old static worker behavior remain compatible. No dependencies.

Compared approaches are extending the old static recipe schema, adding named
scripts per example, and adding a shared typed modeling compiler. Choose the
shared compiler so versioned old contracts stay stable and new operations can
transfer across families. Four examples are fixtures of those shared operations.

## Frozen interface between implementation lanes

New polyforge/blender/modeling.py exports MODELING_CAPABILITIES mapping:
room_kit -> mesh.modeling.room_kit.v1
vehicle -> mesh.modeling.vehicle.v1
mechanical_prop -> mesh.modeling.mechanical_prop.v1
organic -> mesh.modeling.organic.v1
compose -> mesh.modeling.compose.v1
compile_modeling(kind: str, request: dict, *, seed: int=42) -> dict.
New modeling_request.schema.json is strict JSON Schema, no code or source paths.
Request fields schema_version=1.0.0, asset_id identifier<=48, parameters object
with size_m=[width,height,depth] each0.05..50, detail integer1..3 default1,
wall_thickness_m optional0.01..2, max_polygons optional500..100000 default50000,
lod_ratio optional0.1..0.8 default0.5. Compose instead requires objects and
optional sockets with the same definition as plan below. Unknown properties,
nonfinite/boolean numbers, excessive complexity and dangling IDs fail before writes.
Family-specific parameter constraints apply, irrelevant fields are rejected.

Plan schema_version, asset_id, workflow=kind, seed, size_m, max_polygons,
lod_ratio, objects[], materials[], sockets[], input_digest.
Every object has id, primitive (box/cylinder/sphere/curve/grid), size_m,
location=[x,y,z] in Unity coordinates, rotation_deg=[x,y,z], material_id,
export=true/false, modifiers[]. Stable IDs and finite bounded data only.
Curve additionally has points [[x,y,z],...] local Unity coords and bevel_m.
Each modifier is {type:bevel,width_m,segments} OR
{type:subdivision,levels} OR {type:mirror,axis:0|1|2} OR
{type:solidify,thickness_m} OR {type:boolean,target:id,operation:DIFFERENCE|UNION}.
Use strict property sets and bounded levels<=2, segments<=3. Grid primitive is
an explicit Geometry Nodes generated subdivided box with size_m, detail1..3.
Materials are {id,color_rgba} with base,trim,accent fixed reusable palette.
Sockets {id,position:[x,y,z]} use Unity coords within declared bounds.
The compiled root is base-center at zero, native Blender Z-up forward -Y.
No post-hoc rescale that violates requested editing. Objects may overlap only
where the family explicitly declares intended contacts in overlap_policy
('ASSEMBLY_CONTACTS' or 'DISALLOW'). Optional QA field expected_bounds=false
for composition if objects intentionally do not span size_m; bounds must still
stay within declared envelope. Compile ordinary families with expected_bounds=true.

Native producer modeling_worker.py reads job JSON containing plan and output_dir.
It saves source.blend with nondestructive modifier chains, stable semantic_id
properties, root and sockets, emits asset.fbx and lod.fbx from evaluated COPIES,
and source/provenance JSON. It never applies requested modifiers on source.

Independent native modeling_inspector.py reads job JSON containing plan,
source_blend and output_dir. It imports no producer measurement code. It reopens
source, audits evaluated geometry, names, transforms, topology, signed normals,
materials/sockets, budget, modifier preservation, and reports inspection.json.
Pure modeling_inspection.py exposes validate_modeling_report(plan,report)->None.
Inspector report format is owned by inspector lane and supplied to parent.
Technical PASS does not settle silhouette/artistic judgment. Return REVIEW for
unsupported subjective/artistic support. Known-bad geometry must fail.

Parent adapter modeling_adapter.py exposes execute_modeling(kind,inputs,context)
with preflight version5.2.2, dry-run zero writes, separate producer/inspector
owned subprocesses, source hash before/after inspection/export, bounded artifacts,
receipt/identity/crash recovery. Failures preserve logs and do not promote.
Parent integrates registry/CLI/workforce routes. Specialty roles are selected
from kind (architecture/hard_surface/organic_retopo/procedural), with independent
asset inspector. GUI-only or unimplemented requests remain assisted/reference.

## Execution and validation

1. Compiler/schema tests RED -> GREEN before implementation. Check every field,
shape, referential and mesh/resource limit, good/bad/transfer cases.
2. Independent inspector + rejection tests in separate lane. Native producer in
parent lane follows official pinned Blender API references and local probes.
3. Wire normal capability run entry point, workforce routes and bounded context.
4. Run actual Blender four family cases, changed dimensions/details/materials,
compound transfer and invalid topology/pivot/socket tests. Preserve .blend/FBX,
LOD and audit artifacts and screenshots. Native negative cases use disposable
copies. Source hashes stay intact.
5. Import four families with Unity Editor APIs in one isolated managed project.
Check actual meshes, bounds/axes and GUID identity, no serialized-text mutation.
6. Cover mandatory modeling domains with positive/invalid/transfer evidence.
Unknown/manual domains keep truthful status and frozen taxonomy denominator.
7. Full existing offline regression, native v1 arena/animation/sprite affected
regressions, types/lint/format/docs/package checks, independent code review.
8. reports/phase-12.md and phase-specific evidence index. Commit, push to the
user's authorized main destination after verification, inspect latest-head CI.
Advance to Phase13 only when its required development gates pass or a later
explicit user amendment changes them. External true holdout remains separate.
