## Status and process exit

Tool statuses: PASS, FAIL, BLOCKED, NOT_RUN, REVIEW.
Game acceptance: ACCEPTED, PARTIAL, REJECTED; independent from tool status.
The operation_status field always equals status. evaluated_test_status
describes actual tests separately; listing metadata runs no gameplay tests.

| Exit | Meaning |
| --- | --- |
| 0 | Successful operation |
| 2 | Invalid input |
| 3 | Missing dependency |
| 4 | Policy denied or review required |
| 5 | Producer failure or operation not implemented |
| 6 | Contract/invariant failure |
| 7 | Test failure |
| 8 | Retry exhausted |
| 9 | Interrupted |

No failed, blocked, pending-review, or unexecuted operation exits zero.
A successful read-only query may describe tests that were not run.
Canonical build stages are S0 through S5; aliases are not accepted.
report requires both --workspace and --run-id. init uses a positional
new directory; doctor and init do not require an existing workspace.
